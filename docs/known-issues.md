# docs/known-issues.md — 既知の問題と制限

v0.1.0 開発時点（2026-08-03）で分かっている制限、意図的な非対応、まだ検証できていない項目。

意図的にやらないと決めたことも、忘れていることと区別できるようにここに書きます。

## ビルドと CI

### Windows 向け Qt 6.11.x のバイナリが上流に存在しない

**状態**: 回避策を適用済み。CI は緑。

2026-08-02 時点で、Qt は Windows 向けの 6.11.x（6.11.0 / 6.11.1、および 6.12.0）のデスクトップバイナリを `download.qt.io` に公開していません。`aqt list-qt windows desktop --arch 6.11.1` が `Failed to download checksum for the file 'Updates.xml'` で失敗し、`download.qt.io` の該当パス（`windows_x86/desktop/qt6_6111_msvc2022_64/` 等）はディレクトリ一覧に現れるものの実際にアクセスすると 404 を返します。同じ 6.11.1 が macOS（`clang_64`）と Linux（`linux_gcc_64`）では正常に解決するため、Windows 固有の欠落です。

**回避策**: CI の Windows レグだけ Qt `6.10.*` に固定しています（`.github/workflows/ci.yml`）。`find_package(Qt6 6.8 REQUIRED ...)` は下限指定なので 6.10 系も正当なビルド対象です。ローカルで Windows ビルドする場合も 6.10.x を使ってください。

**復帰条件**: 上流が Windows 向け 6.11.x を公開したら、`ci.yml` の Windows レグの `qt_version` を `6.11.*` に戻し、CI が緑であることを確認します。

### clang-tidy は CI に含めていない

チェックセットを MSVC で一度も検証していないため、素性の分からない静的解析ゲートを現在緑の CI に持ち込むリスクを避けています。レビュー担当がローカル（macOS）で手動実行するゲートとして運用しています。手順は [build.md](build.md#clang-tidy-による静的解析)、位置づけは [../AGENTS.md](../AGENTS.md) を参照してください。Windows / MSVC での実行は未検証です。

## 機能の制限（意図的な非対応）

### パスワード保護や暗号化された PDF は開けない

**非対応です。将来対応する予定もありません**（開発者判断、2026-08-02）。

理由: `QPdfWriter` は暗号化された PDF を生成できないため、この経路を検証する自動テスト用のフィクスチャを作れません。テストも人間の実行証跡もないまま実装だけが存在する状態は、機能ではなく負債だと判断し、パスワード再入力の実装ごと削除しました。

挙動: パスワード保護・暗号化された PDF を渡すと、「パスワード保護・暗号化された PDF には対応していません」という理由でそのファイルを失敗として記録し、バッチは次のファイルへ進みます。パスワードの再入力は求めません。この文言は変換前の検査とワーカーの両方で同じものを使うため、どちらの経路を通っても表示は一致します。

回避策: 別のツールで保護を解除してから変換してください。

### そのほか、実装しないと決めていること

| 項目 | 状況 |
| --- | --- |
| PNG 以外の出力形式 | JPEG / TIFF / WebP は v0.2 以降で検討 |
| 変換の並列化 | v0.1 はワーカースレッド 1 本。ファイル単位の並列は v0.2 以降で検討 |
| 出力先ディレクトリの自動作成 | 作りません。既存の書き込み可能なディレクトリを指定してください |
| PDF の編集・結合・分割、OCR、テキスト抽出 | 恒久的に非スコープ |
| クラウド連携・自動更新・テレメトリ | 恒久的に非スコープ（完全オフラインアプリ） |
| Linux 対応 | 動くようには書いていますが CI で検証していません |

## まだ検証できていないこと

自動テストにも CI にも載っておらず、「動くはず」で止まっている項目です。

### GUI の目視確認が未実施

開発がヘッドレス環境で進んだため、次の 3 点は**人間が実際にアプリを操作して確認する必要があります**。

1. `Alt+H` → `Alt+L` の実キー入力でヘルプメニューが開き、ライセンスダイアログが表示されること（Windows / Linux）
2. macOS のネイティブメニューバー上で「ヘルプ」が独立したメニューとして表示され、「ライセンス」が About 相当の場所へ誤って移動していないこと
3. ダークモードでダイアログとメインウィンドウのコントラストが破綻していないこと

（メニューの実装上、アクション名は "About" などの特別語を含まないため macOS が自動で移動させることはない想定ですが、見た目の確認はしていません。）

### ライセンスダイアログの内容を検証する自動テストがない

`ヘルプ > ライセンス` が GPLv3・LGPLv3・Qt のソース入手先・PDFium を表示することは、リポジトリ外の使い捨てドライバプログラムで一度確認しただけです（[progress.md](progress.md) の Task 9 参照）。`tst_main_window` に恒久的なテストケースがないため、文言を壊しても CI では検出できません。

### キャンセルの「1 秒以内」という時間境界を測るテストがない

ページ境界で停止すること、途中まで書き出した PNG が残ることは `tst_converter::cancelStopsAtPageBoundary` で検証済みです。ただし所要時間そのものをアサートするテストはないため、受け入れ基準の「1 秒以内」は未実証です。

### 「変換中に UI が応答し続ける」ことの実測がない

レンダリングをワーカースレッドで行う設計上は満たすはずですが、100 ページの PDF を 300 DPI で変換しながら UI の応答性を実測した記録はありません。

## 配布

### 配布物に署名や公証をしていない

コード署名も、macOS の公証（notarization）も行っていません。CI が生成するアーティファクト（`utsushi-macos-arm64` / `utsushi-windows-x64`）をそのまま実行すると、macOS では Gatekeeper に、Windows では SmartScreen に警告されます。

タグ付きリリースもまだ作成していません。現時点での入手手段はソースからのビルド（[build.md](build.md)）か、CI アーティファクトのダウンロードです。

なお、Qt を環境から取り除いたクリーンな状態で配布物が起動することは、両 OS の CI で継続的に検証しています。
