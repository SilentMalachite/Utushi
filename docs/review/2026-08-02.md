### 1. 依存の向き

**不変条件**: `core/` が `app/` に依存してはならない。`core/` 配下に `#include <QtWidgets/...>` があってはならない。

**根拠**:

- `core/` の全 `.cpp` / `.hpp` を走査した結果、`app/` または `QtWidgets` を include する箇所は 0 件だった。実際の core 内 include も core 自身と Core/Gui/Pdf 系に閉じている（`core/converter.cpp:1-13`、`core/page_range.cpp:1-5`、`core/output_path.cpp:1-4`、`core/render_size.cpp:1-4`）。

### 3. `QPdfDocument` のスレッド局所性

**不変条件**: `QPdfDocument` インスタンスが 2 つ以上のスレッドから触られていない。UI スレッドとワーカースレッドで同一インスタンスを共有していない。

**根拠**:

### 4. UI スレッドのブロック禁止

**不変条件**: レンダリング・ファイル書き込みが UI スレッドで実行されていない。`QCoreApplication::processEvents()` による誤魔化しがない。

**判定**: Pass

**根拠**:

### 5. 上書きの禁止

**不変条件**: 既存の出力ファイルが、ユーザーの明示的な `Overwrite` 指定なしに上書きされていない。

**判定**: Pass

**根拠**:

- 値オブジェクトの既定値は `OverwritePolicy::Skip` である（`core/conversion_job.hpp:8-19`）。UI も Skip を先頭・既定項目として提示し、Overwrite と Rename を明示選択肢に分けている（`app/main_window.cpp:95-103`）。
- 保存前に出力パスの存在を検査し、Skip は保存せず、Rename は未使用の `_N` パスへ変更し、明示的な Overwrite だけが同じパスへ進む（`core/converter.cpp:190-203`）。
- 同一バッチ内の stem 衝突は、サニタイズと case folding 後のキーで保存前に拒否される（`core/converter.cpp:66-116`）。
- Skip / Rename / Overwrite の各動作と UI からのポリシーマッピングはテストされている（`tests/tst_converter.cpp:238-316`、`tests/tst_main_window.cpp:128-193`）。
- ただし `QFileInfo::exists()` と `QImage::save(fileName)` の間には競合窓がある（`core/converter.cpp:190-203`）。別プロセスがその間に同名ファイルを作ると、Skip/Rename でも後発の保存が既存内容を切り詰め得る。Qt の `QIODevice::WriteOnly` は既存ファイルに対して既定で Truncate を含み、排他的作成を保証するのは `QIODevice::NewOnly` である。したがって通常経路のテストは通るが、不変条件の絶対的な上書き禁止は満たさない。

### 6. エラーの非握り潰し

**不変条件**: `QPdfDocument::Error` と `QImage::save()` の戻り値がすべて検査されている。バッチ処理が 1 件の失敗で全体停止していない。

**判定**: Fail

**根拠**:

- 観測事実: UI probe と worker document の `load()` 戻り値は検査され、`QImage::save()` の `bool` も検査されている（`app/main_window.cpp:220-239`、`core/converter.cpp:129-137`、`core/converter.cpp:203-211`）。不正 PDF とページ単位のレンダリング失敗は後続へ進む（`core/converter.cpp:134-138`、`core/converter.cpp:180-188`）。不正 PDF を挟んだバッチ継続テストもある（`tests/tst_converter.cpp:209-236`）。
- 違反: 個別の `image.save(outPath, "PNG")` が 1 回失敗すると `summary.aborted = true` として即座に `return` し、同じファイルの後続ページと後続ジョブをすべて放棄する（`core/converter.cpp:203-211`）。これは「バッチ処理が 1 件の失敗で全体停止していない」という不変条件に反する。
- 仕様の独立評価: CLAUDE.md は「出力先に書き込めない」場合の全体中止を定める一方（`CLAUDE.md:127-133`）、直後に 1 件の失敗でバッチを止めないとも定めている（`CLAUDE.md:135`）。コードには開始前のディレクトリ単位検査が別にある（`core/converter.cpp:118-127`）。したがって、ディレクトリ検査通過後の単一 `outPath` 保存失敗まで無条件に全体中止へ格上げするのは範囲が広すぎる。現契約ではページ失敗として記録して継続し、全体中止はディレクトリ自体が使用不能と確認できた場合に限定するのが整合的である。
- 動的検証の限界: パスワード再試行経路は実装上エラーを検査している（`app/main_window.cpp:220-239`）が、テスト側の `QPdfDocument::Error` 使用は正常 PDF の `None` 確認だけである（`tests/tst_converter.cpp:69-71`）。暗号化 PDF の実行証拠がない点は観測済みのテストギャップであり、このレビューでは挙動成功を推定していない。
- 別の違反: `buildJobs()` は `IncorrectPassword` を最初の分岐に使う一方、再ロード後を含む全エラーを「PDF として読み込めません」に統合する（`app/main_window.cpp:224-239`）。そのため `FileNotFound`、`InvalidFileFormat`、誤パスワード、`UnsupportedSecurityScheme` をユーザーが区別できず、`CLAUDE.md:125-135` の「すべてユーザーに識別可能な形で提示」に反する。事前検査で弾かれたジョブは `core/converter.cpp:18-31` の詳細な `loadErrorText()` に到達しない。

**具体的な是正**: `QImage::save()` 失敗をページ失敗として進捗へ反映し、次のページ・ファイルへ `continue` する。失敗した出力パスをディレクトリとして先に作るクロスプラットフォームな回帰テストを追加し、後続ジョブが成功することを固定する。最小 diff は「3. 違反一覧」の最初の指摘に示す。
