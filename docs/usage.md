# docs/usage.md — 使い方と仕様

Utsushi は PDF を PNG 連番画像に変換します。ネットワーク通信は行いません。読み書きするのはユーザーが指定したローカルファイルだけです。

---

## 画面の項目

| 項目 | 内容 |
| --- | --- |
| **入力 PDF** | 変換する PDF の一覧。`ファイルを追加...` で追加、`選択を削除` で除去します。複数選択できます |
| **ページ範囲** | 空欄で全ページ。`1-5,8,11-` 形式（後述） |
| **解像度 DPI** | 72 / 150 / 300 / 600 のプリセット。編集可能なので任意の数値も入力できます。既定は 300 |
| **出力先** | PNG を書き出すディレクトリ。`参照...` で選択できます |
| **既存ファイル** | 出力先に同名ファイルがあるときの扱い。スキップ（既定）/ 上書きする / 別名で保存 |
| **変換開始 / キャンセル** | 変換中は「変換開始」「ファイルを追加」「選択を削除」が無効になり、「キャンセル」だけが有効になります |
| **進捗** | プログレスバーと、その下のテキスト（「ファイル 2/3: 120 ページ中 37 ページ完了」）の両方で示します |
| **結果** | 変換後のサマリ。読み取り専用 |

`ヘルプ > ライセンス` から本アプリと Qt のライセンス告知を表示できます。

---

## 変換の手順

1. `ファイルを追加...` で PDF を選ぶ（複数可）
2. ページ範囲・DPI・出力先・既存ファイルの扱いを指定する
3. `変換開始`

**出力先ディレクトリは事前に存在している必要があります。** Utsushi はディレクトリを作りません。存在しない・書き込めない場合は変換を開始せず、「出力先が書き込み可能なディレクトリではありません」と表示します。

---

## ページ範囲の指定

| 入力 | 意味 |
| --- | --- |
| （空欄） | 全ページ |
| `3` | 3 ページ目のみ |
| `1-5` | 1〜5 ページ |
| `1-5,8` | 1〜5 ページと 8 ページ |
| `11-` | 11 ページ目から最終ページまで |
| `1-3,2-4` | 重複は除去され `1,2,3,4` になります |

- ページ番号は **1 始まり**です（PDF ビューアの表示と一致します）。
- 指定順に関わらず、変換は昇順で行われます。
- 次はすべて不正な指定として扱われます: 逆順（`5-1`）、0 以下（`0`、`-3`）、そのファイルの総ページ数を超える番号、数値以外（`abc`）、空のトークン（`1,,3`）。

**ページ範囲はバッチ内の全ファイルに同じものが適用され、検証は各ファイルのページ数に対して個別に行われます。** たとえば `11-` を指定して 20 ページの PDF と 5 ページの PDF を同時に変換すると、20 ページのほうは 11〜20 ページが変換され、5 ページのほうだけが「ページ範囲指定が不正です」として失敗します。バッチは止まりません。

## 解像度（DPI）

出力ピクセルサイズは次の式で決まります。

```
ピクセル = round(ページのポイントサイズ / 72 × DPI)
```

- 幅・高さとも最低 1px を保証します。
- **1 辺が 20000px を超えるページは変換されません。** そのページは「DPI が大きすぎます」として失敗し、残りのページは処理を続けます。
- 小数（`96.5` など）も指定できます。0 以下や数値として読めない値は不正です。

A4（595 × 842 pt）の場合の目安:

| DPI | 出力サイズ |
| --- | --- |
| 72 | 595 × 842 px |
| 150 | 1240 × 1754 px |
| 300 | 2479 × 3508 px |
| 600 | 4958 × 7017 px |

**DPI が不正な場合だけは、バッチ全体が 1 件も変換されずに終わります**（ファイルごとの失敗ではなく、設定そのものの誤りとして扱うため）。結果には「DPI の値が不正です: ...」だけが表示されます。

## 出力ファイル名

```
{入力 PDF のファイル名（拡張子なし）}_p{ゼロ埋めページ番号}.png
```

例: `report.pdf` の 7 ページ目（全 120 ページ）→ `report_p007.png`

- ゼロ埋めの桁数は **その PDF の総ページ数の桁数**です（ページ範囲で選んだ枚数ではありません）。ただし最低 3 桁。
  - 全 120 ページ → 3 桁（`_p007`）
  - 全 1500 ページ → 4 桁（`_p0007`）
  - 全 9 ページ → 3 桁（`_p007`。最低 3 桁の保証による）
- ファイル名に使えない文字（`\ / : * ? " < > |` と制御文字）は `_` に置き換えます。
- Unicode は NFC に正規化します（macOS の NFD で作られたファイル名でも同じ結果になります）。
- 前後の空白は除去し、その結果が空になった場合は `output` を使います。

### 同じ出力名になるファイルがバッチ内にあるとき

異なる PDF でも、同じ出力先に対して同じファイル名を生成することがあります（`~/a/report.pdf` と `~/b/report.pdf` はどちらも `report_p001.png` になります）。この場合、**最初に現れたファイルだけを変換し、以降の同名衝突は変換せず失敗として報告します。** 黙って消えたり、同じバッチ内で先の出力を壊したりしないためです。

サニタイズ後に同じ名前になる場合（`a:b.pdf` と `a?b.pdf` はどちらも `a_b`）や、大文字小文字だけが違う場合（`Report.pdf` と `report.pdf`）も衝突として扱います。macOS と Windows の既定のファイルシステムは大文字小文字を区別しないためです。

同じファイルを一覧に 2 回追加しただけの場合は、実害がないので別の文言で報告します（最初の 1 回だけ変換されます）。

## 既存ファイルの扱い

出力先に同名の PNG がすでにあるときの挙動を選べます。**既定は「スキップ」で、黙って上書きすることはありません。**

| 設定 | 挙動 |
| --- | --- |
| **スキップ（既定）** | そのページは書き込まず、結果の「スキップ」件数に加算します |
| **上書きする** | 既存ファイルを置き換えます |
| **別名で保存（`_2` を付与）** | `report_p001.png` が埋まっていれば `report_p001_2.png`、それも埋まっていれば `_3`… と空き番号を探します |

スキップと別名保存では、「存在を確認してから書く」のではなく保存先を排他的に確保してから書き込みます。確認と書き込みの間に別のプロセス（別の Utsushi など）が同名ファイルを作った場合でも、明示的な「上書きする」指定なしに中身を壊すことはありません。

---

## 進捗とキャンセル

- 進捗はプログレスバーと**テキストの両方**で示します（「ファイル 2/3: 120 ページ中 37 ページ完了」）。
- 変換はワーカースレッドで実行するため、変換中も UI は応答します。
- **キャンセル**を押すとページの境界とファイルの境界で停止します。処理中のページの完了を待つだけなので、すぐに止まります。
- **キャンセルしても、そこまでに書き出された PNG は残ります。** 削除はしません。

---

## 結果の読み方

変換後、結果欄の先頭にサマリが出ます。

```
成功: 240 ページ / 失敗: 2 件 / スキップ: 0 ページ
[失敗] /Users/me/broken.pdf: PDF として読み込めません
[失敗] /Users/me/report.pdf の 13 ページ目: ページのレンダリングに失敗しました
```

- **成功** はページ数、**失敗** は件数（ファイル単位の失敗とページ単位の失敗の合計）、**スキップ** はページ数です。
- ファイル全体の失敗は `[失敗] パス: 理由`、特定ページの失敗は `[失敗] パス の N ページ目: 理由` の形式です。
- **1 件の失敗でバッチ全体は止まりません**（出力先に書き込めない場合を除く）。壊れた PDF が混ざっていても、残りのファイルは変換されます。

進捗テキストの最終状態は次のいずれかになります。

| 表示 | 意味 |
| --- | --- |
| 完了 | 変換を最後まで実行しました（個々の失敗があっても含みます） |
| キャンセルされました | ユーザーが中断しました。途中までの PNG は残っています |
| 中止しました | 出力先に書き込めず、バッチ全体を中止しました |
| 変換できるファイルがありませんでした | すべてのファイルが変換前の検査で弾かれ、1 ページも変換を試みていません |

## エラーメッセージ一覧

### 変換を開始できないとき

| メッセージ | 原因 | 対処 |
| --- | --- | --- |
| 入力 PDF がありません | 一覧が空です | `ファイルを追加...` で PDF を追加してください |
| 出力先が書き込み可能なディレクトリではありません | 出力先が未指定、存在しない、ディレクトリでない、書き込み権限がない | 既存の書き込み可能なディレクトリを指定してください。Utsushi はディレクトリを作りません |
| DPI の値が不正です: *入力値* | 数値として読めない、または 0 以下 | 正の数値を入力してください |

### ファイル単位の失敗

| メッセージ | 原因 | 対処 |
| --- | --- | --- |
| ファイルが見つかりません | 追加後にファイルが移動・削除された | 一覧から削除して追加し直してください |
| PDF として読み込めません | PDF として不正、または破損している | ファイルそのものを確認してください |
| パスワード保護・暗号化された PDF には対応していません | 非対応です（意図的） | 別のツールで保護を解除してから変換してください（[known-issues.md](known-issues.md#パスワード保護や暗号化された-pdf-は開けない)） |
| ページ範囲指定が不正です: *入力値* | そのファイルのページ数に対して範囲指定が成立しない | 範囲指定を見直してください。ファイルごとにページ数が違う点に注意 |
| 出力ファイル名が *パス* と重複するため変換していません | 同じ出力先に同じ名前で書き込むファイルが先にあった | 出力先を分けるか、入力ファイル名を変えてください |
| 同じファイルが変換対象に複数回追加されています | 同じファイルを重複して追加しています | 実害はありません。最初の 1 回だけ変換されます |
| 出力先に書き込めません: *パス* | 変換中に出力先が消えた、権限が変わった | **これだけはバッチ全体を中止します。** 出力先を確認してください |

### ページ単位の失敗

| メッセージ | 原因 | 対処 |
| --- | --- | --- |
| DPI が大きすぎます | 出力の 1 辺が 20000px を超えます | DPI を下げてください |
| ページのレンダリングに失敗しました | そのページの描画に失敗しました | 他のページは変換されます。PDF 側の問題の可能性があります |
| PNG の保存に失敗しました: *パス* | 書き込みに失敗（容量不足など） | 空き容量と権限を確認してください。このファイルの他のページとバッチの残りは続行します |
| ページ番号が範囲外です | 内部整合性の検査に引っかかりました | 通常は発生しません |
| 別名保存先の候補を確保できませんでした: *パス* | 「別名で保存」で空き番号が見つかりませんでした | 出力先を整理するか、別のディレクトリを指定してください |

## キーボード操作

すべての操作がキーボードだけで完結します。

**タブ順序**

入力 PDF 一覧 → ファイルを追加 → 選択を削除 → ページ範囲 → 解像度 DPI → 出力先 → 参照 → 既存ファイル → 変換開始 → キャンセル → 結果

- `Tab` / `Shift+Tab` で移動、`Space` でボタンを実行、`Enter` は「変換開始」（既定のボタン）を実行します。
- Windows / Linux では `Alt+A`（ファイルを追加）、`Alt+P`（ページ範囲）、`Alt+D`（DPI）、`Alt+O`（出力先）、`Alt+E`（既存ファイル）、`Alt+S`（変換開始）、`Alt+C`（キャンセル）、`Alt+H` →`Alt+L`（ヘルプ > ライセンス）が使えます。
- **macOS ではニーモニック（`Alt+文字`）は Qt の既定で無効です。** `Tab` と `Space` / `Enter` を使ってください。すべてのコントロールに `Tab` で移動するには、システム設定 > キーボード > 「キーボードナビゲーション」を有効にする必要があります。

**その他のアクセシビリティ方針**

- アニメーション・フェード・スライドを使いません。状態の変化は即時です。
- 成功と失敗は色ではなく `[失敗]` という文言で区別します。
- 進捗はプログレスバーだけでなくテキストでも示します。
